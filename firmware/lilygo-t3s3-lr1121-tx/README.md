# LILYGO T3S3 V1.2 + LR1121 reference transmitter

This PlatformIO project turns the LILYGO T3S3 V1.2 LR1121 board into a
repeatable LoRa test transmitter for the ZynqSDR receiver and MATLAB IQ
inspection workflow.

The default profile is deliberately conservative:

| Parameter | Default |
|---|---:|
| Frequency | 868.1 MHz |
| Bandwidth | 125 kHz |
| Spreading factor | SF7 |
| Coding rate | 4/5 |
| Sync word | `0x12` (private) |
| Preamble | 12 symbols |
| Header | explicit |
| Payload CRC | enabled |
| IQ inversion | disabled |
| Output power | 0 dBm |
| Packet interval | 500 ms |
| Payload | 32-byte `ZLP1` counter frame |

Periodic transmission is **stopped after boot**. Start it explicitly over USB
or with the BOOT button.

## Safety and RF connection

Always connect an antenna or a correctly rated RF load before transmitting.
For a conducted bench test, use the existing 30 dB attenuator:

```text
T3S3 SMA -> 30 dB attenuator -> optional DC block -> ZynqSDR RX
```

Do not connect the transmitter directly to the SDR input. Begin at 0 dBm and
verify the received level before increasing power.

The project defaults to the standard non-PA LR1121 board shown in the project
photos. For the external-PA board variant, add
`-DLILYGO_LR1121_PA_VERSION=1` to `build_flags`. The firmware then uses the
LILYGO PA RF-switch tables and limits high-band output power to 0 dBm.

The tested T3-S3 LR1121 unit reports the radio use-case byte as `0xF3` while
the documented LR1121 identifier is its low nibble, `0x03`. RadioLib otherwise
rejects the chip with error `-2`. The small `LilygoLR1121` adapter accepts this
board-specific value without modifying the RadioLib package. For a unit that
reports the standard value, change `kRadioDeviceId` in `include/board_config.hpp`
to `0x03`.

## Build and flash

Install PlatformIO Core or use the PlatformIO extension in VS Code:

```bash
cd firmware/lilygo-t3s3-lr1121-tx
pio run
pio run --target upload
pio device monitor
```

The first radio transaction is delayed by 1500 ms, matching LILYGO's reference
startup sequence. OLED/I2C initialization is performed only after LR1121 has
responded successfully.

If automatic upload does not start, hold **BOOT**, press and release **RESET**,
start the upload, then release **BOOT**.

## Serial commands

The monitor runs at 115200 baud. Use `help` to print the complete command list.
Typical first session:

```text
show
set freq 868.1
set bw 125
set sf 7
set cr 5
set power 0
set preamble 12
set interval 500
start
```

Useful commands:

```text
show
start
stop
send
set freq <MHz>
set bw <kHz>
set sf <5..12>
set cr <5..8>
set power <dBm>
set preamble <symbols>
set sync <byte>
set crc <on|off>
set iq <normal|inverted>
set interval <ms>
set length <12..220>
payload counter
payload hex <hex-bytes>
```

Every transmission produces one parseable log line:

```text
TX seq=17 len=32 state=0 start_ms=11420 duration_ms=57
```

`state=0` is a successful RadioLib transmission. The BOOT button toggles
periodic transmission; the OLED shows the active profile and sequence number.

## Counter payload format

The default counter frame is deterministic and easy to recognize in IQ/packet
decoder tests:

| Byte offset | Size | Meaning |
|---:|---:|---|
| 0 | 4 | ASCII magic `ZLP1` |
| 4 | 4 | sequence number, unsigned little-endian |
| 8 | 4 | ESP32 `millis()`, unsigned little-endian |
| 12 | variable | incrementing byte pattern derived from sequence |

The LoRa explicit header and two-byte payload CRC are generated by LR1121 and
are not part of this application payload.

## Board mapping

The pin map follows LILYGO's T3S3 V1.2/V1.3 LR1121 definition:

| Signal | GPIO |
|---|---:|
| LR1121 SCLK / MISO / MOSI / CS | 5 / 3 / 6 / 7 |
| LR1121 RESET / BUSY / DIO9 | 8 / 34 / 36 |
| OLED SDA / SCL | 18 / 17 |
| BOOT button | 0 |
| LED | 37 |

The standard LR1121 RF switch is controlled internally through LR1121 DIO5 and
DIO6. The board uses a 3.0 V TCXO setting.
