# Визуализация опорных CSS chirp в MATLAB

В MATLAB-модели репозитория опорный CSS chirp формируется функцией
[`lora_phy.reference_chirp`](../../model/matlab/+lora_phy/reference_chirp.m).
Для быстрой визуальной проверки добавлен пример
[`plot_reference_chirps.m`](../../model/matlab/examples/plot_reference_chirps.m).

Пример показывает один `upchirp` и один `downchirp` в четырёх представлениях:

1. I/Q во времени;
2. развёрнутая фаза;
3. мгновенная частота;
4. спектр.

Это удобно использовать как floating-point golden reference перед переносом
генератора chirp в Simulink и HDL.

## Параметры примера

По умолчанию используются:

- `SF = 7`;
- `BW = 125 kHz`;
- `samplesPerChip = 4`;
- `Fs = BW * samplesPerChip = 500 kHz`;
- число chip на символ `N = 2^SF = 128`;
- число отсчётов на символ `N * samplesPerChip = 512`;
- длительность символа `Ts = 2^SF / BW = 1.024 ms`.

Конфигурация создаётся через:

```matlab
config = lora_phy.css_config(7, 4);
```

## Как формируется chirp

В `reference_chirp.m` фаза задаётся в циклах:

```matlab
phaseCycles = 0.5 * n.^2 / ...
    (config.symbolCount * config.samplesPerChip^2) - ...
    0.5 * n / config.samplesPerChip;
chirp = exp(2j * pi * phaseCycles);
```

Если обозначить

- `N = 2^SF`;
- `L = samplesPerChip`;

то для `upchirp`:

```text
phi[n] = 0.5*n^2/(N*L^2) - 0.5*n/L    cycles
x_up[n] = exp(j*2*pi*phi[n])
```

`downchirp` строится как комплексно-сопряжённый сигнал:

```matlab
downchirp = conj(upchirp);
```

Поэтому направление изменения мгновенной частоты у двух сигналов
противоположное, а амплитуда остаётся единичной.

## Запуск

Из каталога `model/matlab`:

```matlab
addpath examples
[result, figureHandle] = plot_reference_chirps;
```

Функция автоматически сохраняет рисунок в:

```text
docs/images/css-reference-chirps-sf7-bw125.png
```

Можно передать собственный путь:

```matlab
[result, figureHandle] = plot_reference_chirps("chirps.png");
```

Структура `result` содержит сами комплексные chirp, фазу, мгновенную частоту,
частотную ось и нормированный спектр, поэтому пример можно использовать не
только для рисунка, но и для численной проверки.

## Что должно быть видно на графиках

### I/Q

`I` и `Q` изменяются синусоидально, при этом модуль комплексного сигнала должен
оставаться равным единице:

```text
abs(x[n]) = 1
```

Это важная проверка перед fixed-point и HDL-реализацией: генератор chirp не
должен создавать амплитудную модуляцию.

### Фаза

Развёрнутая фаза имеет квадратичный закон. Для `downchirp` знак фазы меняется,
так как он является комплексно-сопряжённой версией `upchirp`.

### Мгновенная частота

Она вычисляется через приращение комплексной фазы соседних отсчётов:

```matlab
phaseStep = angle(x(2:end) .* conj(x(1:end-1)));
f = phaseStep * Fs / (2*pi);
```

Для `upchirp` частота линейно возрастает примерно от `-BW/2` до `+BW/2`, а для
`downchirp` — убывает в обратном направлении.

### Спектр

Спектр chirp занимает полосу порядка `BW`. В примере FFT вычисляется с
нулевым дополнением для более удобной визуализации. Нулевое дополнение не
повышает реальное спектральное разрешение, а только делает кривую плотнее.

## Использование как golden reference для FPGA

Этот пример полезно сохранить как первый контрольный уровень цепочки:

```text
MATLAB floating point
        ↓
Simulink / fixed point
        ↓
HDL chirp generator or ROM/NCO
        ↓
FPGA
```

При переносе генератора chirp в HDL имеет смысл проверять отдельно:

1. число отсчётов на символ;
2. начальную фазу;
3. закон приращения фазы;
4. направление `upchirp/downchirp`;
5. постоянство амплитуды;
6. мгновенную частоту;
7. спектр;
8. комплексную ошибку HDL относительно MATLAB после квантования.

Для ROM-реализации MATLAB-вектор можно квантовать и сравнить с содержимым ROM.
Для NCO/DDS-реализации удобнее сравнивать фазовый аккумулятор и приращение
фазы. Это позволяет локализовать ошибку ещё до проверки полного LoRa
демодулятора.

## Связь с LoRa-символами

`reference_chirp` генерирует базовый CSS chirp. Информационный символ в модели
формируется функцией
[`lora_phy.modulate_symbol`](../../model/matlab/+lora_phy/modulate_symbol.m) как
циклический сдвиг базового `upchirp`.

Таким образом, рекомендуемая последовательность проверки PHY выглядит так:

```text
reference_chirp
      ↓
modulate_symbol
      ↓
dechirp
      ↓
FFT / correlator
      ↓
symbol decision
```

Важно: базовый chirp сам по себе не является полным LoRa-пакетом или полной
стандартной преамбулой. Для пакетного уровня в репозитории используются
отдельные функции построения и приёма LoRa-пакетов.
