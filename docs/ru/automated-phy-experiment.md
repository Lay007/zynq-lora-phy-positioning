# Передача, запись и анализ с одного компьютера

Скрипт `tools/run_phy_experiment.py` выполняет весь первый PHY-эксперимент с
одной Windows-машины:

```text
настройка передатчика через USB serial
                 ↓
запуск и готовность записи PlutoSDR или RTL-SDR
                 ↓
передача отдельных пакетов с подтверждением
                 ↓
завершение записи и расчёт SHA-256
                 ↓
автоматический анализ в MATLAB
                 ↓
raw IQ, логи, metadata, JSON, MAT и PNG-отчёт
```

Serial-протокол уже поддерживает эталонная прошивка LILYGO LR1121. Для будущей
прошивки Heltec SX1262 следует реализовать те же команды `stop`, `set ...`,
`show` и `send`. Тогда сценарий на компьютере не будет зависеть от модели
передающей платы.

## Установка

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[hardware,dev]"
```

Для PlutoSDR дополнительно нужны Analog Devices IIO runtime и работающая
команда `iio_info -s`. Для RTL-SDR программа `rtl_sdr.exe` должна находиться в
`PATH`. MATLAB должен запускаться командой `matlab`; другой полный путь можно
указать в `analysis.matlab_command`.

## Конфигурация и безопасная проверка

Скопируйте пример и исправьте COM-порт, разрешённую частоту, gain и адрес SDR:

```powershell
Copy-Item experiments/configs/one-machine-pluto.example.json `
  experiments/configs/my-pluto.local.json
```

Сначала проверьте план без открытия serial-порта и без обращения к SDR:

```powershell
python tools/run_phy_experiment.py `
  --config experiments/configs/my-pluto.local.json `
  --dry-run
```

Dry-run проверяет длительность записи относительно числа пакетов и выводит все
команды передатчика и приёмника.
Перед `--execute` замените `bench.antenna_or_cable_path = "EDIT BEFORE RUN"`
описанием реального расположения антенн либо полного кабельного тракта с
аттенюаторами. Пока остаётся заглушка, реальный запуск запрещён.

## Запуск опыта

После подключения правильных антенн либо рассчитанного кабельного тракта с
достаточным ослаблением:

```powershell
python tools/run_phy_experiment.py `
  --config experiments/configs/my-pluto.local.json `
  --execute
```

Для RTL-SDR используйте `one-machine-rtl-sdr.example.json`. Ключ
`--skip-analysis` позволяет временно не запускать MATLAB: raw-запись и
метаданные всё равно сохранятся.

Результат находится в `artifacts/phy-runs/<UTC>-<run-name>/`:

```text
experiment-config.json       точная входная конфигурация
run.json                     состояние, commit, подтверждения TX, hashes
transmitter.log              команды и ответы serial с UTC-временем
receiver.stdout.log          вывод программы записи
receiver.stderr.log          диагностика программы записи
capture/*.cf32 или *.cu8      неизменённая raw IQ-запись
capture/*metadata.json       фактические настройки Pluto
analysis/*inspection.json    краткие оценки параметров
analysis/*inspection.mat     полная структура результата MATLAB
analysis/*inspection.png     визуальный отчёт из четырёх панелей
analysis/*matlab.log         журнал пакетного запуска MATLAB
```

Pluto-рекордер создаёт признак готовности только после настройки приёмника и
отбрасывания прогревочных буферов. Оркестратор ждёт его и короткую задержку
`post_arm_delay_s`, чтобы блокирующее чтение RX успело начаться, и лишь затем
отправляет `send`. У `rtl_sdr` такого интерфейса нет, поэтому проверяется, что процесс не
завершился, и выдерживается `arm_delay_s`.

## Безопасность и граница точности времени

- Значение 0 dBm в примере не доказывает безопасность конкретного соединения
  или законность выбранной частоты. До запуска проверьте регион, вариант платы,
  антенны, допустимый вход SDR и ослабление кабельного тракта.
- Скрипт передаёт отдельные пакеты и не включает бесконтрольный периодический
  режим. Для каждого пакета обязателен ответ `TX ... state=0`.
- Доступ к serial и реальная RF-передача требуют явного ключа `--execute`;
  отсутствие и `--execute`, и `--dry-run` считается ошибкой.
- При ошибке запись останавливается, в `run.json` остаётся состояние `failed`,
  а частичные raw-файлы сохраняются для диагностики.
- USB serial и запуск процессов обеспечивают координацию записи, но не точную
  RF-метку времени. Этого достаточно для проверки PHY и визуализации. Для
  ToA/TDoA потребуются аппаратные timestamps в PL либо общий trigger/clock.
