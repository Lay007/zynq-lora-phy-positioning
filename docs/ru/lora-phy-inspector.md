# LoRa PHY Inspector

LoRa PHY Inspector — собственный MATLAB-инструмент проекта для исследования и
верификации IQ-записей. Он находит самую сильную CSS/LoRa-посылку, оценивает её
параметры, сопоставляет профиль с семействами LoRa-радиочипов и показывает
промежуточные представления, которые затем используются в Simulink и RTL.

![LoRa PHY Inspector](../images/lora-phy-inspector.png)

## Запуск

Из корня репозитория:

```matlab
cd model/matlab
addpath apps
app = lora_phy_inspector;
```

Русский интерфейс:

```matlab
app = lora_phy_inspector("on", Language="ru");
```

Для проверки без SDR можно сформировать детерминированную запись:

```matlab
addpath examples
file = generate_inspector_demo_capture;
app = lora_phy_inspector;
app.FileField.Value = file;
app.SampleRateField.Value = 500e3;
```

Нажмите **Analyze / Анализ**. Интерфейс доступен на английском и русском языках;
язык меняет только подписи, но не алгоритмы, метрики и пороги проверки.

## Входные поля

- **IQ recording / IQ-запись** — комплексная запись без заголовка.
- **Format / Формат** — `auto`, `cu8`, `cf32` или `ci16`.
- **Sample rate / Частота дискретизации** — фактическая частота дискретизации.
- **Center frequency / Центральная частота** — частота настройки SDR; для чистой
  baseband-симуляции можно указать `0`.
- **Expected carrier / Ожидаемая несущая** — ожидаемая частота передатчика; при
  ненулевом значении Inspector выводит CFO относительно неё.
- **TX checkpoint / Контрольная точка TX** — автоматический выбор по имени HDL
  PCM или ручное переопределение номера точки.

Поддерживаемые форматы:

| Формат | Расширения | Порядок компонентов | Масштаб |
|---|---|---|---|
| RTL-SDR CU8 | `.cu8`, `.uc8` | unsigned 8-bit `I,Q,I,Q,...` | примерно `[-1,1]` |
| Pluto/GNU Radio CF32 | `.cf32`, `.fc32`, `.cfile` | little-endian float32 `I,Q,I,Q,...` | как в файле |
| CI16/SC16 | `.pcm`, `.ci16`, `.sc16` | little-endian signed int16 `I,Q,I,Q,...` | делится на 32768 |

## HDL CI16

HDL testbench сохраняет обычный complex-int16 поток:

```text
I0, Q0, I1, Q1, ...
```

Каждая компонента — signed `int16` little-endian. В HDL
`data_out[31:16] = I`, `data_out[15:0] = Q`, а testbench записывает байты как
`I_lo,I_hi,Q_lo,Q_hi`.

`phase_to_sample` сейчас выдаёт приблизительно Q14-амплитуду (`±16384`). Это
свойство сигнала, а не отдельный файловый формат. После нормировки CI16 на
32768 номинальная амплитуда HDL chirp около `0.5`.

Имя HDL-записи обязано содержать параметры:

```text
hdl_sf<SF>_bw<BW_KHZ>k_fs<FS_KHZ>k_<TAG>.pcm
```

Примеры:

```text
hdl_sf7_bw125k_fs2000k_package.pcm
hdl_sf7_bw125k_fs2000k_chirp-h17-up.pcm
hdl_sf5_bw500k_fs8000k_chirp-h0-up.pcm
hdl_sf7_bw125k_fs2000k_chirp-h64-down.pcm
```

Helper рядом с сигналами:

```matlab
cd hdl/signal
open_in_inspector("hdl_sf7_bw125k_fs2000k_package.pcm")
```

извлекает SF/BW/Fs, выбирает `ci16`, выставляет Fs и включает автоматическую
проверку относительно MATLAB golden-модели.

## Контрольные точки TX

Inspector разделяет три уровня результата:

- **Входные данные** — CI16 успешно загружен, а SF/BW/Fs/stage разобраны из
  имени записи;
- **Контракт точки** — проверяется геометрия и длина потока конкретной TX stage;
- **MATLAB golden** — проверяется форма сигнала относительно исполняемого
  эталона MATLAB.

Итоговый `PASS` означает, что пройдены и контракт, и доступная golden-проверка.
При `FAIL` основная причина выводится прямо в верхней строке Inspector и
дублируется в диагностическом окне. Для точек без исполняемого эталона
используется `NOT VERIFIED`, а не ложный `PASS`.

Stage 1 теперь параметрический по частоте дискретизации. Для одиночного chirp
не требуется `Fs = 2 MHz`: необходимо, чтобы отношение `L = Fs/BW` было целым,
а длина записи соответствовала

```text
Ns = 2^SF * L.
```

Например, `SF5 / BW500 kHz / Fs8 MHz` даёт `L=16` и `Ns=512` и является
корректной геометрией Stage 1. Stage 2 пока сохраняет текущий production-контракт
`2.000 MS/s`; Stage 3–5 имеют свои фиксированные частоты и пока возвращают
`NOT VERIFIED`, пока в репозитории нет точных production golden-моделей.

## Сравнение с MATLAB golden

Для корректно названной HDL CI16-записи Inspector автоматически сравнивает
сигнал с авторитетной MATLAB-моделью `reference_chirp` / `modulate_symbol`.

Для файла с тегом `package` проверяется текущая последовательность package. Для
одиночной записи вида `chirp-h17-up` или `chirp-h64-down` номер символа и
направление берутся из имени.

Перед сравнением Inspector ищет лучший сдвиг в небольшом окне около заданной
границы символа и удаляет только один постоянный комплексный коэффициент
амплитуды/фазы. После этого выводятся:

- **Golden EVM**;
- нормированная **Golden correlation**;
- RMS и максимальная фазовая ошибка;
- максимальная ошибка комплексного отсчёта;
- поправка границы символа в отсчётах;
- медианная ошибка фазового приращения в **Q16 LSB/sample**;
- RMS ошибки фазового приращения в градусах на отсчёт;
- итог **PASS/FAIL**.

Диагностика фазового шага предназначена именно для RTL/DDS-отладки. Например,
устойчивая оценка около `-4 Q16 LSB/sample` означает систематическое отличие
фазового приращения HDL от MATLAB golden примерно на четыре младших разряда
16-битного фазового слова на каждом отсчёте.

Текущие пороги PASS рассчитаны именно на цифровую HDL-регрессию: EVM `<= 1 %`,
correlation `>= 0.999`, RMS phase error `<= 1°`. Пороги не ослаблялись при
параметризации Stage 1. Это внутренние регрессионные критерии проекта, а не
норматив LoRaWAN/RF-сертификации.

То же ядро доступно без GUI:

```matlab
metrics = lora_phy.compare_iq_to_golden( ...
    iq, 8e6, 5, 500e3, StartIndex=1, Symbol=0, Direction="up");
```

Полезные диагностические поля:

```matlab
metrics.evmPercent
metrics.correlation
metrics.rmsPhaseErrorDegrees
metrics.medianPhaseIncrementErrorQ16Lsb
metrics.rmsPhaseIncrementErrorDegrees
```

## Сопоставление с LoRa-радиочипами

После оценки SF и BW Inspector формирует профиль, например:

```text
LoRa / SF7 / BW 125 kHz
PACKET_TYPE_LORA
```

и сопоставляет его с встроенной таблицей возможностей Semtech. Если известна
RF-частота, учитывается и диапазон частот. Сейчас таблица покрывает наиболее
полезные для проекта SX126x/SX127x, LLCC68 и SX1280/SX1281.

Для текущего проектного профиля SF7/BW125 отдельно показывается **SX1262** как
reference radio, поскольку тестовые Heltec V4.3 используют SX1262. При этом
Inspector может показать и другие совместимые чипы. По форме IQ-сигнала нельзя
однозначно доказать, какой именно физический чип был передатчиком — это только
сопоставление возможностей.

LoRaWAN DR автоматически не назначается: номер data rate зависит от региона.

## Как читать четыре графика

1. **Full recording: spectrogram** — вся запись и найденные границы посылки.
2. **Detected CSS/LoRa burst** — амплитуда и мгновенная частота.
3. **Average spectrum** — занятая полоса и оценка несущей.
4. Для обычной записи — **Per-symbol dechirped FFT** по символам. Для HDL
   Stage 1 — спектр остатка после дечирпа непосредственно MATLAB golden для
   выбранного `h` и направления. В идеальном случае энергия остатка
   концентрируется в нулевом bin.

Для передискретизированного сигнала каждая строка объединяет мощности FFT всех
polyphase-представлений на chip rate. Список справа содержит диагностические
FFT-bin решения, а не подтверждение полного packet decode.

## Что оценивается

Inspector:

1. находит наиболее сильную непрерывную посылку;
2. оценивает занятую полосу и carrier offset;
3. выбирает ближайшую стандартную BW 62.5/125/250/500 кГц из разрешённых для
   текущего анализа кандидатов;
4. оценивает SF5…SF12;
5. уточняет начало первого upchirp;
6. оценивает residual CFO;
7. выводит SNR, относительную мощность, DC offset, I/Q imbalance и clipping;
8. сопоставляет PHY-профиль с совместимыми радиочипами;
9. для HDL CI16 проверяет контракт TX stage и, где возможно, MATLAB golden;
10. для Stage 1 показывает фазовую диагностику, пригодную для локализации
    систематических DDS/RTL-ошибок.

Алгоритмы не требуют Communications Toolbox и Signal Processing Toolbox.

## Ограничения

- Анализируется только самая сильная посылка.
- Мощность не является калиброванным RSSI/dBm.
- Radio identification показывает совместимость, но не идентифицирует
  физический чип однозначно.
- Golden PASS/FAIL — внутренний критерий регрессии, а не сертификационный тест.
- Stage 3–5 пока не имеют точных исполняемых production golden-моделей.
- Для полного стандартного LoRa packet decode используется отдельный
  `receive_lora_packet`.
- Потоковый приём напрямую из PlutoSDR/RTL-SDR пока не реализован.

Для независимой визуальной проверки запись можно открыть в Inspectrum или
SDRangel; gr-lora_sdr полезен как независимая реализация LoRa-приёмника.
