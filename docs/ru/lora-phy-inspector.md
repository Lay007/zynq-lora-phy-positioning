# LoRa PHY Inspector

LoRa PHY Inspector — собственный MATLAB-инструмент проекта для исследования
IQ-записи до декодирования пакета. Он загружает запись, находит самую сильную
CSS-посылку, оценивает её основные параметры и показывает промежуточные
представления, которые затем станут блоками Simulink и RTL-приёмника.

![LoRa PHY Inspector](../images/lora-phy-inspector.png)

## Запуск

Из корня репозитория:

```matlab
cd model/matlab
addpath apps
app = lora_phy_inspector;
```

Инструмент можно проверить без SDR. Сначала сформируйте детерминированную
тестовую запись:

```matlab
addpath examples
file = generate_inspector_demo_capture;
app = lora_phy_inspector;
app.FileField.Value = file;
app.SampleRateField.Value = 500e3;
```

Нажмите **«Анализировать»**. В примере находится исследовательский кадр SF7,
BW 125 кГц со смещением +40 кГц относительно центра записи.

## Что вводить

- **IQ-файл** — запись комплексных отсчётов без заголовка.
- **Формат** — `auto`, `cu8` или `cf32`. В режиме `auto` формат определяется
  по расширению файла.
- **Fs** — фактическая частота дискретизации IQ в отсчётах в секунду.
- **Центр** — частота настройки SDR в герцах. Она нужна для вывода абсолютной
  оценки несущей.
- **Ожидаемая частота** — номинальная частота передатчика. Если она неизвестна,
  оставьте ноль; иначе программа рассчитает CFO относительно неё.

Поддерживаются следующие представления:

| Формат | Расширения | Порядок компонентов | Масштаб |
|---|---|---|---|
| RTL-SDR CU8 | `.cu8`, `.uc8` | беззнаковые 8-битные `I,Q,I,Q,...` | приводится примерно к `[-1,1]` |
| Pluto/GNU Radio CF32 | `.cf32`, `.fc32`, `.cfile` | little-endian float32 `I,Q,I,Q,...` | сохраняется как в файле |

Raw-файл не содержит метаданных. Вместе с каждой записью сохраняйте Fs,
центральную частоту, усиление, настройки радиомодуля и идентификатор опыта по
[методике записи](iq-capture-guide.md).

## Как читать четыре графика

1. **Спектрограмма всей записи** показывает найденную посылку и её границы.
   Здесь видны клиппинг, помехи, зеркальные компоненты и ошибка выбора центра.
2. **Найденная посылка** совмещает амплитуду и мгновенную частоту, вычисленную
   по разности фаз. Upchirp выглядит как восходящая пила с периодическим
   переносом частоты, downchirp — как нисходящая.
3. **Средний спектр** показывает занятую полосу, оценку несущей и границы
   выбранной стандартной BW.
4. **Dechirp FFT по символам** содержит символы по строкам, FFT bins — по
   столбцам. Повторяющиеся upchirps преамбулы дают одинаковые яркие пики.
   Downchirp при умножении на эталонный upchirp не превращается в один тон и
   выглядит размазанным по строке.

Список справа содержит жёсткие решения по максимуму FFT. Это диагностические
номера bins, а не подтверждение успешного декодирования стандартного пакета.

## Что и как оценивается

Текущая версия выполняет следующие шаги:

1. считает энергию коротких блоков и выбирает самую сильную непрерывную
   посылку;
2. по распределению мгновенной частоты оценивает занятую полосу и несущую,
   затем выбирает ближайшую BW 125, 250 или 500 кГц;
3. сравнивает нормированную автокорреляцию на возможных периодах символа и
   оценивает SF5…SF12;
4. уточняет начало первого upchirp по концентрации энергии после dechirp и FFT;
5. по повторяющимся upchirps оценивает остаточную частотную ошибку;
6. выводит относительную мощность сигнала и шума, SNR, DC offset, дисбаланс
   мощностей I/Q и долю клиппированных компонентов CU8.

Алгоритмы не требуют Communications Toolbox и Signal Processing Toolbox.
Ядро можно использовать без графического окна:

```matlab
[iq, info] = lora_phy.load_iq_capture("capture.cf32", "auto");
result = lora_phy.inspect_iq_capture(iq, 1e6);
```

## Ограничения измерения

- Анализируется только самая сильная посылка; переключения между несколькими
  пакетами пока нет.
- Мощность относится к масштабу отсчётов в файле. Это не калиброванный RSSI и
  не мощность в dBm.
- Оценка BW и SF предполагает LoRa-подобную CSS-преамбулу и стандартный набор
  параметров.
- GUI Inspector остаётся средством оценки неизвестной записи. Для известного
  профиля BW/SF стандартный sync word/header и waveform реального SX1262 уже
  декодирует [`receive_lora_packet`](lora-packet-decoder.md).
- Потоковый приём непосредственно из PlutoSDR и RTL-SDR пока не реализован:
  сначала нужно записать IQ в файл.

Для независимой визуальной проверки тот же файл можно открыть в
[Inspectrum](https://github.com/miek/inspectrum). SDRangel удобен при живом
наблюдении эфира, а [gr-lora_sdr](https://github.com/tapparelj/gr-lora_sdr)
можно использовать как независимую реализацию LoRa-приёмника. Эти программы
дополняют, но не заменяют прослеживаемую цепочку MATLAB → Simulink данного
проекта.
